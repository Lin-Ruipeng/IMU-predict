# 预处理数据格式

本文档独立描述 `preprocessing` 模块消费的原始 IMU 数据、生成的积分角度及其
校验约定。领域术语以仓库根目录的 `GLOSSARY.md` 为准。

## 原始文件

模块每次只读取指定 `data/` 子目录中的直属 CSV，不递归读取更深目录。标准文件名
必须以以下字段之一结尾：

- `...gyro.csv`：原始角速度。
- `...accel.csv`：原始加速度；v1 正常忽略，不读取内容、不配对、不输出。

`gyro(1).csv` 等名称不是标准格式。模块会明显提示并跳过，不会自动删除 `(1)`、
改名或猜测其含义。同名文件可能出现在不同受试者目录中，因此文件身份包含其在
`data/` 下的相对路径。

同一目录内，如果两个文件只在 `gyro` 与 `accel` 字段上不同，则属于同一采集
会话。例如：

```text
VID_20260918_203521gyro.csv
VID_20260918_203521accel.csv
```

只有同一采集会话的加速度才可能用于增强角速度分析；v1 尚未实现这种增强。

## CSV 列

原始文件没有必须存在的表头。模块无条件舍弃第一物理行而不解析，以兼容首行是
表头的数据来源；对于当前无表头文件，这意味着第一个数值样本也会被舍弃。

从第二物理行开始，每行必须恰好包含四列：

```text
x,y,z,timestamp_ns
```

- gyro 的前三列是设备坐标系 x、y、z 轴角速度，单位为 rad/s。
- accel 的前三列是设备坐标系 x、y、z 轴加速度，单位为 m/s²；是否包含重力未知。
- 第四列是严格递增的传感器时间戳，单位为 ns。时钟起点未知，不能解释为 Unix
  时间；本模块只使用相邻差值。
- 当前资料不足以定义三个设备轴的实际正方向。

示例 gyro 行：

```text
-0.009162972,0.008246674,-0.03054324,342769574748488
```

## 固定步长与积分

舍弃第一物理行后，文件必须至少保留两个有效样本。令相邻传感器时间戳差的
中位数为固定周期 `dt`，估算频率为 `1 / dt`。绝对频率不受硬编码范围限制。

若输入共有 N 个物理行，舍弃首行后得到 `retained[0]` 至
`retained[N-2]`，输出仍有 N 个数据行。第 0 行为零初值；每个保留样本恰好贡献
一次：

```text
angle[0] = (0, 0, 0)
angle[j+1] = angle[j] + retained[j] * 180 / pi * dt
elapsed[j+1] = (j+1) * dt
```

这里的积分角度是逐轴累计的相对角位移，不是姿态、朝向或 Euler 角，也没有进行
漂移校正或坐标系旋转。

模块同时检查单文件内的采样稳定性。满足任一条件时打印 WARNING，但仍生成结果：

- 超过 1% 的相邻间隔与中位周期相差 10% 以上。
- 任一相邻间隔大于中位周期的 2 倍。

## 输出

输入目录：

```text
data/<relative-path>/
```

对应输出目录：

```text
outputs/preprocessing/<relative-path>/
```

每个 `VID_...gyro.csv` 生成 `VID_...integrated_angle.csv`。输出是不带表头的四列
CSV：

```text
x_deg,y_deg,z_deg,elapsed_s
```

第 4 列是从 0 开始、严格按固定 `dt` 增长的合成相对时间，不保留原始时间戳抖动。
输出目录还包含 `preprocessing_config.json`，记录该批次实际使用的 `input_dir` 与
`force` 参数。已有结果默认不会被覆盖，只有显式设置 `force=true` 才会原子替换。

## 当前数据审计

对当前本地 `data/` 的只读检查得到：

- 787 个标准 `...gyro.csv`。
- 245 个标准 `...accel.csv`。
- 0 个非标准编号文件；此前 19 个 `...gyro(1).csv` 已在确认无目标冲突后显式
  移除 `(1)`，该操作不是模块的自动修复行为。
- 标准 gyro 的中位周期估算频率约为 206.95–500.08 Hz。
- `VID_20260918_203303gyro.csv` 示例约为 471.73 Hz，中位周期约 2.119844 ms。

这些统计描述当前数据集，不是未来输入的绝对频率约束。

## 调用

完整命令行参数：

```bash
uv run imup preprocess --input-dir "data/<relative-path>" [--force]
```

或使用 JSON：

```bash
uv run imup preprocess --config "outputs/path/to/config.json"
```

```json
{
  "input_dir": "data/<relative-path>",
  "force": false
}
```

两种参数来源互斥。JSON key 必须与命令行参数一一对应，JSON 中的相对路径始终以
仓库根目录为基准。
